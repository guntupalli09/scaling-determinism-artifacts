# Phase 3 on Kaggle's free GPU

**Status:** prepared and smoke-tested on CPU (see *What has been tested*). **Not yet run on a GPU**, so no
Phase 3 result exists yet.

| File | Purpose |
|---|---|
| `phase3_kaggle.ipynb` | the notebook (generated by `build_notebook.py`) |
| `phase3_driver.py` | resumable, budget-aware runner; enforces Step A → B → C gating |
| `phase3_report.py` | writes `PHASE3_VALIDATION_REPORT.md` + `phase3_status.json` from the saved state only |
| `kaggle_remote.py` | push / status / fetch through the official Kaggle CLI (no browser) |

Only the free **GPU T4 x2** accelerator is used. Nothing is purchased; nothing is tuned. A session stops
itself after 11 h, below Kaggle's 12 h limit, so its output is saved. Kaggle's free GPU quota is about 30 h
per week.

## What it runs

**GPU 0: CUAD.**
- RoBERTa-base Step A comes first. It is scored by the pre-registered `comparators/cuad_step_a.py`
  (commit `09e7990f`).
- Only on `STEP_A_PASS` do Step B (all 618 frozen documents × 41 categories) and Step C (paired
  units vs engine v7.2.0, exact McNemar, written to its own directory) run.
- RoBERTa-large and DeBERTa-v2-xlarge then follow the same path.

**GPU 1: ContractNLI Span NLI BERT-base**, in parallel.
- Training uses the authors' code at `058c56f` with `conf_base.yml`, seed 42, pinned to one GPU so the
  published batch size holds.
- Then `test.py`, then the pre-registered `comparators/gpu/contractnli_step_a.py`.
- Pairing runs only on `STEP_A_PASS`.

**Data.**
- `fetch_external.sh` downloads CUAD, ContractNLI and the official `evaluate.py` from their public sources
  and checks every SHA-256.
- `build_corpus.py` then rebuilds the corpus. The driver refuses to run unless the rebuilt
  `manifest.csv` equals the frozen `3bcd0d90…` and all 618 text hashes match.

## Persistence and resume

- Everything that matters is in `/kaggle/working/phase3_state/`, which Kaggle saves as the version's output:
  checkpoints after every CUAD question, Step A results, paired units, logs, environment records.
- The next session resumes from it in either of two ways:
  - **remote:** `kaggle_remote.py push --resume-state <fetched>/phase3_state`;
  - **manual:** *Add Input → Your Work → Notebooks → this notebook*.
- ContractNLI training cannot resume inside `train.py`. It therefore only starts when at least 5 h of budget
  remain, and a partial run is discarded.

## The only manual actions

1. **Kaggle account:** phone-verify it. Kaggle requires this for GPU and Internet.
2. **Pick one:**
   - **Remote (recommended).** Kaggle → *Settings → API → Create New Token*. Add the two values as
     `KAGGLE_USERNAME` and `KAGGLE_KEY` in this Claude Code cloud environment's settings, under network
     secrets or environment variables. Claude then pushes, monitors, fetches and commits the results itself.
     The token has full API access to the Kaggle account; it is used only for the private notebook and its
     private state dataset.
   - **Manual.**
     1. Kaggle → *Create → Notebook → File → Import Notebook*, and give it the GitHub URL of
        `experiments/followup/comparators/kaggle/phase3_kaggle.ipynb` on branch
        `claude/adoring-heisenberg-gd2tv1`.
     2. Set *Accelerator: GPU T4 x2* and *Internet: On*.
     3. *Save Version → Save & Run All*.
     4. Repeat with the previous output attached until the report says COMPLETE.

## What has been tested (CPU, this repository's cloud container)

- **No-GPU guard:** the driver records `BLOCKED_NO_GPU` and exits; the report shows the blocker.
- **Data path, real:**
  - fresh clone + `fetch_external.sh` from the public sources → all hashes OK;
  - `build_corpus.py` reproduces manifest `3bcd0d90…` and all 618 text hashes.
- **ContractNLI environment and code path:** see `SMOKE_CONTRACTNLI.md`. Install, training steps, model save, `test.py`, Step A key paths and the pairing format all pass; the dev-evaluation step could not be tested on CPU (out of host RAM). Python 3.8 + authors' pins,
  CPU torch; a tiny subset with 4 training steps; `test.py`; Step A key paths. This found two dependency
  breaks, now pinned. **Smoke only; it says nothing about accuracy.**
- **Report renderer:** checked on synthetic in-progress / failed states in a scratch directory; nothing
  synthetic is committed.
- `evaluate_paired.py --out-dir`: the engine-only output is byte-identical to the frozen v7.2.0 files.

**Not tested:**
- anything on a GPU;
- Kaggle's own image;
- `kaggle_remote.py` against a real account (there are no credentials in this environment).
